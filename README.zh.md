# TriliumNext Flux

> 个人日常项目任务管理 · TriliumNext 插件

> **简体中文 | [English](./README.md)**

## 项目简介

把「以项目达成目标」这件事，在 Trilium 笔记里变成每天看得见、做得完的任务面板。

TriliumNext Flux 是一个运行在 [TriliumNext](https://github.com/TriliumNext/Trilium) 中的 Render 插件，以**项目**为核心组织你的日常任务：

- **项目驱动**：进行中 / 暂停 / 循环阶段项目分组展示，进度一目了然
- **当天优先**：逾期与今日、计划任务、收集箱自动归类，打开面板就知道今天该做什么
- **辅助习惯**：周打卡与间隔计时提醒，帮你保持执行节奏

**特点**

| | |
|---|---|
| 数据自主 | 全部保存在 Trilium 笔记内，无外部存储、无第三方服务 |
| 无依赖 | 纯前端实现，零第三方库 |
| 中英双语 | 界面语言一键切换 |
| 灵活配置 | 各功能可开关，标签语法可自定义 |
| 轻量 | 30 秒自动刷新，不引入额外负担 |

## 安装方法

### 前提

- 已安装 **TriliumNext**（0.105.0版及以上，低于此版本可能也支持，只是我没有测试过）
- 从 [Releases 下载页](https://github.com/ZangXincz/TriliumNext-Flux/releases) 下载最新插件 zip 包

### 导入步骤

1. 如之前未开启过`后端脚本执行`，需要在`设置`->`安全` 中开启

2. **导入插件压缩包**：在 Trilium root目录，鼠标右键，导入到笔记，选择zip包，取消勾选安全导入
   ![alt text](./docs/importzip.png)

   导入图示
   ![alt text](./docs/importgraphic.png)

3. 创建一个Home页，笔记类型为`渲染笔记`，设置属性`~renderNote=TriliumNext Flux` 和`~configNote=config`，保存后F5刷新
![alt text](./docs/HomeNoteType.png)

这样就基本配置完成了，后续可以在设置进行基础修改和查看基本使用说明
![alt text](./docs/set.png)


## 使用方法

插件面板把笔记里带复选框（checkbox）的任务自动抓取并分组展示。所有标签都是写在任务文本里的 `#标记`，下面逐一说明。

### 面板总览

面板自上而下分为若干分组（可在设置中开关）：

| 分组 | 内容 |
|---|---|
| 逾期与今日 | 今天到期与已逾期的任务 |
| 进行中的项目 | `state=In-Progress` 的项目卡片 |
| 暂停 / 等待响应 | `state=On-Hold` 的项目卡片 |
| 循环阶段项目 | `state=Cycling-Phase` 的项目卡片 |
| 收集箱 | 收集箱笔记及其子树里的任务 |
| 计划任务 | 标注了未来日期的任务 |
| 打卡 | 带 `#checkin` / `#dk` / `#habit` 标签的打卡卡片 |
| 间隔计时提醒 | 带 `#tx` / `#timer` / `#pomodoro` 标签的计时卡片 |

面板每 30 秒自动刷新，也可以手动触发刷新。

### 任务

#### 基本写法

在任何 text 笔记里写普通的任务列表即可（Trilium 的待办列表），插件会自动识别：

```markdown
- [ ] 写周报
- [ ] 给老王回邮件
- [ ] 预约体检
```

面板会自动把这些任务汇总展示，点击行首的 **✓** 即可完成（写入后端、勾选置灰淡出）。

#### 指定日期

在任务文本中标注日期，插件会按到期时间自动归类：

```markdown
- [ ] 提交季度报销 #2026-08-28
- [ ] 整理旅行照片 #2026-09-05
```

- 日期为**今天** → 显示在「逾期与今日」（标记「今日」）
- 日期为**已过期** → 显示在「逾期与今日」（标记「逾期」）
- 日期为**未来** → 显示在「计划任务」

#### 打开笔记

点击任务行右侧的 **↗** 会打开任务所在笔记，并直接跳转到对应复选框。

### 重复任务

用 `#repeat` 标签让任务按固定周期自动推进，适合「每天 / 每周 / 每月 / 每年」的固定任务：

```markdown
- [ ] 晨间复盘 #2026-08-27 #repeat:1d
- [ ] 更新项目周报 #2026-08-31 #repeat:1w
- [ ] 信用卡还款 #2026-08-25 #repeat:1m
- [ ] 年度体检 #2026-08-27 #repeat:1y
```

语法：`#repeat:<间隔><单位>`，间隔为正整数，单位为 `d`（天）/ `w`（周）/ `m`（月）/ `y`（年）。

**规则**：

- 按计划推进：完成时把当前计划日期写进历史，任务上的 `#日期` 自动推进为下一次，复选框恢复未勾选，无需手动改日期。
- 位置型：后缀 `:start`（每月初）/ `:end`（每月底）/ `:endwork`（每月末工作日）可**省略 `#日期`**，插件会自动计算并补写当前周期的计划日期。
- 按实际完成：后缀 `:actual` 表示从**实际完成那天**起算下一次——断更多天后补做，不会把错过的日期补齐，只按真实完成节奏顺延。

```markdown
- [ ] 交房租 #repeat:1m:start        # 每月 1 号
- [ ] 月底复盘 #repeat:1m:endwork    # 每月最后一个工作日
- [ ] 背单词 #2026-08-27 #repeat:1d:actual   # 断更后从实际完成日顺延
```

每次完成，任务下方会自动生成一条**历史子任务**（勾选状态，含完成日期）。历史超过 4 条时自动折叠为「…中间已完成 N 次…」，只保留最早 2 条与最新 2 条，不影响计数。

### 项目

在任意笔记上打上 `state` 标签即成为项目卡片：

| 标签值 | 显示位置 |
|---|---|
| `state=In-Progress` | 进行中的项目 |
| `state=On-Hold` | 暂停 / 等待响应 |
| `state=Cycling-Phase` | 循环阶段项目 |

项目卡片的排序可用 `#priority` 标签控制（P1 最高，P2、P3 依次，没有该标签的排最后）：

```markdown
state=In-Progress
#priority=P1

- [ ] 完成首页设计
- [ ] 联调登录接口
```

卡片上会显示项目内复选框的完成进度 `done/total`，点击卡片打开项目笔记。

> 范围说明：默认扫描全部笔记中带 `state` 标签的笔记；若在设置中配置了「项目上级目录」，则只统计这些目录（含子树）内的项目卡片。

### 收集箱

适合先把没想好放哪里的想法、零散待办随手记下来，之后再整理。不需要写日期、不需要挂项目：

```markdown
- [ ] 想到一个读书会点子，改天整理
- [ ] 帮同事带杯咖啡
```

**识别方式**：标题匹配「收集箱标题」的笔记（默认 `inbox` / `收集箱`，可在设置中自定义，逗号分隔）及其**整棵子树**都被视为收集箱，位于任意层级都生效。

**显示行为**：

- 收集箱里的任务**单独成组展示**（面板「收集箱」分组），不混入「逾期与今日」/「计划任务」。
- 勾选、打开笔记等操作与普通任务一致。
- 在设置中**关闭「收集箱」开关**后，收集箱任务不再单独成组，而是**按日期回落到普通分组**——带 `#日期` 的照常显示在「逾期与今日」或「计划任务」，没日期的也会出现在对应位置。

### 周打卡

适合「每周完成 N 天」的长期习惯。在任务文本中写：

```markdown
- [ ] 早起 #checkin:5
- [ ] 跑步 #checkin:4:2
```

语法：`#checkin:<每周目标天数>`，可选 `:<每天最多次数>`。

- `#checkin:5`：每周目标 **5 天**，每天最多打卡 **1 次**。
- `#checkin:4:2`：每周目标 **4 天**，每天最多 **2 次**。当天打满 2 次才算完成 1 天，周进度按**天数**计（不是次数）。
- 默认同时识别 `#dk` / `#habit` 标签，也可在设置中自定义标签列表。

**使用方式**：

- 打卡卡片展示「本周周一~周日」7 个格子，点击任意格子即打卡。
- 当天次数未满 → 点击 +1；已满 → 再点清零（取消当天打卡）。
- 打卡记录自动写入任务下方的子列表，格式随界面语言：中文仅中文周名、英文仅英文周名，示例：
  - 中文界面：`20260824~20260830 dk1周：周一(1/2)，周二(2/2)（周进度4/6）`
  - English UI: `20260824~20260830 dk1w(Week 1): Mon(1/2), Tue(2/2) (Weekly 4/6)`
- 历史记录按周（周一~周日为范围）折叠，最新周在前，本周进度实时显示 `完成天数/目标天数`。

### 间隔计时提醒

适合番茄钟、工作/休息节奏管理。在任务文本中写：

```markdown
- [ ] 深度工作 #tx:50:10
- [ ] 写论文 #tx:25:5:专注:放松
- [ ] 冥想 #tx:30
```

语法：`#tx:<进行分钟>:<休息分钟>:<进行时名称>:<休息时名称>`，后两段自定义阶段名（可选）。

- `#tx:50:10`：进行 50 分钟，休息 10 分钟。
- `#tx:25:5:专注:放松`：阶段显示为「专注」与「放松」。
- `#tx:30`：只写进行时长，休息分钟用设置中的默认值（默认 5 分钟）。

**使用方式**：

- 点「开始」进入进行阶段，倒计时走完后自动进入「待休息」，按设定的方式提醒你（弹窗 / 全屏 / 声音，可在设置中勾选，可多选）。
- 点「开始休息」进入休息阶段；休息结束会再次提醒，可重新开始。
- 点「重置」可随时回到待开始状态。
- 计时状态会自动持久化到配置笔记，**刷新页面后倒计时自动恢复**，不会丢。

默认同时识别 `#tx` / `#timer` / `#pomodoro` 标签，可在设置中自定义。

### 设置

点击面板右上角的 **⚙️ 设置** 打开设置弹窗，共 5 个 Tab，每个 Tab 底部都附有对应的 `#标记` 使用指南：

| Tab | 配置项 |
|---|---|
| 基础设置 | 语言（中文 / English）、是否启用插件、版本信息、GitHub 仓库 |
| 任务 | 开关：逾期与今日 / 计划任务 / 收集箱；收集箱标题（逗号分隔） |
| 项目 | 开关：进行中的项目 / 暂停与等待响应 / 循环阶段项目；项目上级目录（逗号分隔，留空扫全树） |
| 打卡 | 打卡功能开关；打卡标签（逗号分隔，任一匹配即识别） |
| 提醒 | 提醒功能开关；提醒标签；默认休息分钟；提醒方式（弹窗 / 全屏 / 声音，可多选） |

**保存前提**：设置会写入宿主笔记 `~configNote` 关系指向的配置笔记（`json` 或 `code` 类型）。首次保存前请确保已按「安装方法」添加该关系，否则会提示「未找到配置笔记」。

- **保存**：仅更新改动字段，配置笔记里手动添加的其他字段会保留。
- **恢复默认**：将整份默认配置写回（有确认提示）。

### 数据来源与扫描范围

| 数据类型 | 扫描范围 |
|---|---|
| 任务 / 打卡 / 提醒 | 全树所有 text 笔记（按 `#标签` 解析） |
| 收集箱 | 标题匹配「收集箱标题」的笔记及其整棵子树（可位于任意层级） |
| 项目卡片 | 配置了「项目上级目录」→ 仅这些目录（含子树）内有 `state` 的笔记；未配置 → 全树带 `state` 的笔记 |

### 常见问题

**Q1：面板提示「未找到配置笔记」怎么办？**
在宿主笔记上添加关系 `configNote`，指向一个 `json` 或 `code` 类型的配置笔记，保存后 F5 刷新。没有配置笔记时插件用内置默认配置运行，但无法保存设置。

**Q2：勾选任务没有反应？**
确认后端脚本执行已开启（设置 → 安全），且插件以 Render 笔记形式运行（`~renderNote` 关系）。

**Q3：计时状态刷新后不见了？**
计时状态保存在配置笔记的 `txState` 字段中；若没有配置笔记则无法持久化（计时仍可运行，只是刷新后重置）。

**Q4：打卡格子上的次数是什么意思？**
`#checkin:4:2` 中每天最多 2 次。格子上 `1/2` 表示今天已打 1 次、共 2 次；打满后格子显示已满，再次点击清零。

**Q5：为什么重复任务会多出历史子任务？**
那是插件自动写入的完成记录（含完成日期）。普通任务没有重复标签，勾选后不会生成历史，只标记完成。
